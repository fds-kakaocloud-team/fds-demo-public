# 모의 이체 판정 기준

웹의 무작위 거래 입력 버튼은 미리 정한 정상·차단 테스트 사례와 여러 값을 섞어 입력란을 채웁니다. 버튼 자체는 추론이나 거래 저장을 하지 않습니다. 다음 → 이체하기를 눌러야 요청이 전송됩니다. 반복하면 동일한 사례가 나올 수도 있습니다. 입력값은 실제 정답이 아닙니다.

`POST /transactions`는 두 Random Forest의 사기 클래스 점수(`predict_proba`)를 별도로 계산하고, **어느 하나라도** 해당 모델에 저장된 기준값 이상이면 Abuse / block, 둘 다 미만이면 Normal / approve를 반환합니다. 모델을 다시 학습하면 기준값은 달라질 수 있습니다.

| 모델 | 입력 | 현재 기준값 | 학습 데이터 |
|---|---|---:|---|
| PaySim | 금액, 거래 전 잔액, 거래 유형 | 약 0.5656 | 공개 합성 모바일 거래 데이터 |
| 시간·거리 | 거래 시간(0~23), 직전 거래 위치와의 거리(km) | 약 0.58 | 직접 생성한 가상 데이터 |

웹의 거래 유형은 이체(`TRANSFER`)로 고정됩니다. 시간은 입력된 시각 그대로 사용하며, 거리는 사용자가 직접 입력합니다. 실제 위치나 거래 이력으로 거리를 계산하지 않습니다. 받는 은행·계좌·이름은 화면 확인용이며 모델 입력이나 서버 저장에 사용하지 않습니다.

각 점수는 여러 결정 트리의 출력을 합친 모델 값입니다. 특정 금액이나 시간만으로 무조건 사기라고 결정하는 고정 규칙은 아닙니다. 학습 및 표본 추출과 클래스 가중치의 영향이 있어 점수를 실제 사기 발생 확률로 해석할 수 없습니다. 기준값은 각각의 검증 데이터에서 PaySim은 F1, 시간·거리 모델은 정상·사기 탐지율 평균(균형 정확도)을 기준으로 선택했습니다.

별도 테스트에서는 PaySim의 사기 재현율이 91.1%이고 시간·거리 모델은 27.3%였습니다. 두 모델을 합친 정책은 공동 정답 데이터로 평가하지 않았습니다. 각 모델의 수치를 합산 정책의 성능으로 주장할 수 없으며, 현재 결과는 시연용입니다. 차단 화면 알림과 감사 이벤트 기록을 구현했고 외부 보안 알림 연동은 아직 없습니다.
