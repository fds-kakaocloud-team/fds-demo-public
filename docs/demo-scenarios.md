# 로컬 통합 시연

웹의 계좌 이체에서 정상 사례, 거래 이상 사례, 시간·거리 이상 사례 버튼을 눌러 입력값을 채운다. 아래 금액·잔액·시간·거리는 현재 저장된 모델 파일에 대한 예시이며, 모델 재학습 시 결과는 달라질 수 있다.

| 사례 | 금액 | 출금 전 잔액 | 시간 | 거리(km) | 기대 결과 |
|---|---:|---:|---:|---:|---|
| 정상 | 10,000 | 100,000 | 12 | 5 | 승인 |
| 거래 모델 차단 | 100,000 | 100,000 | 12 | 5 | 차단: `paysim` |
| 시간·거리 모델 차단 | 10,000 | 100,000 | 2 | 1,000 | 차단: `time_location` |

화면에서 다음 → 이체하기를 누르고 결과의 모델별 점수와 기준, 차단 원인을 확인한다. 거래 내역과 보안 알림에서 거래 ID로 같은 거래를 확인한다. API 문서(`/docs`)의 `GET /audit-events`에서 거래 ID와 차단 사유를 확인할 수 있다. 계좌 정보는 시연용이며 실제 계좌 조회, 출금 및 입금은 수행하지 않는다.

자동 검증: `python -m unittest discover -s tests -v`. 통합 시나리오 테스트는 임시 SQLite를 사용하며 실 모델, 판정별 감사 이벤트, 잘못된 입력, 감사 저장 실패 시 거래 기록 롤백을 확인한다. PaySim 모델이 없으면 이 테스트는 건너뛴다.

## 모델 평가 및 한계

- PaySim: 시간순 테스트 103,573건에서 정상 101,973건 중 101,833건 정상 판정, 사기 1,600건 중 1,458건 탐지. 사기 재현율 91.1%, 정밀도 91.2%. 합성 모바일 거래 데이터의 결과다.
- 시간·거리: 자체 생성 가상 데이터 테스트 2,000건에서 정상 1,945건 중 1,739건 정상 판정, 사기 55건 중 15건 탐지. 사기 재현율 27.3%, 정밀도 6.8%.
- 두 모델을 OR로 묶은 정책은 공동 정답이 있는 데이터로 평가하지 않았다. 따라서 PaySim 단독 수치를 통합 정책 성능으로 주장할 수 없다. 시간·거리 모델은 규칙으로 생성한 라벨을 학습했으며 현 상태는 시연용이다.
